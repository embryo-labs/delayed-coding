# AVX-512 DC: sub-nanosecond coding and a local throughput model

2026-09-14. Research prototype based on `7e6c5a2b216967682ad33b045cd277f2dea549a1`.
This report does **not** replace the calibrated rANS comparison or claim a new
rANS victory. It measures a new DC implementation against a 1 ns/symbol target.

## Result

Both encoding and decoding are below 1 ns/symbol on book1, on one physical CPU
thread, with either 12-bit or 16-bit probability precision. These are separate
operation times, **not** their sum and not end-to-end Blitzcrank performance.

| Effective probability precision | Encode ns/symbol | Decode ns/symbol | Payload bytes | Main decode lookup |
| --- | ---: | ---: | ---: | ---: |
| 12 bits | 0.8577 | 0.3924 | 441862 | 16 KiB |
| 16 bits | 0.8599 | 0.9203 | 441260 | 512 KiB |

The selected pair is `encode64_into` / `decode64_bounded`: cumulative intervals,
exact DC capacity arithmetic, delay threshold 16, 64 interleaved states, 16-bit
physical words, u32 input/output, prebuilt models and reusable buffers.
64 states means **four SIMD vectors of sixteen lanes**, not 64 CPU threads.

Cells are medians across five process runs per precision. Each process reports
seven-sample medians, each sample encoding or decoding 21 complete book1 blocks
(16144191 symbols). Precision order alternates between trials; codec order within
a process is fixed. Across all five runs:

- P12 encoding: 0.8568–0.8584; decoding: 0.3923–0.3926 ns/symbol.
- P16 encoding: 0.8573–0.8629; decoding: 0.9184–0.9211 ns/symbol.

These demonstrate repeatability on this machine, not confidence intervals or a
guarantee for arbitrary inputs. [Complete raw rows](results/2026-09-14-avx512-book1.csv)
retain slower lane counts and scalar controls as well.
[Build metadata](results/2026-09-14-avx512-metadata.txt) records the measured binary
hash; rebuilding the final source reproduced it exactly.

## Co-design choices

### 1. Change the state bound, not just the instruction spelling

This is **not Log-DC**. The capacity schedule is the original integer recurrence:

```
virtual = capacity >= 65536
normalized_capacity = virtual ? capacity >> 16 : capacity
next_capacity = normalized_capacity * frequency
```

Before multiplication, `1 <= normalized_capacity < 65536`, and
`1 <= frequency <= 65536`. Therefore `next_capacity < 2^32`.
The information numerator satisfies `0 <= n < capacity`; the decoder checks the
normalized form of this invariant before SIMD multiplication, even for corrupt
input. Since remainder < frequency, `n*frequency + remainder < next_capacity`.
Both capacity and numerator fit unsigned 32-bit lanes **exactly**.

With delay 24 the generic bound is 40 bits, requiring wider state representation.
Reducing the delay to 16 enables sixteen lanes in a 512-bit vector. Multiplication
is retained; the key change is the number of independent updates per instruction.

Lower delay is not free compression-wise. Holding model, mapping and **64 lanes**
fixed, the independent scalar encoder gives:

| Precision | Delay 24 bytes | Delay 16 bytes | Increase |
| --- | ---: | ---: | ---: |
| 12 | 435842 | 441862 | 1.3812% |
| 16 | 435296 | 441260 | 1.3701% |

This is ordinary integer normalization loss at a smaller delay threshold, **not
logarithm approximation**. Finite-block behavior is distribution-dependent; for
constant data, the smaller startup cost can instead make delay 16 smaller.

### 2. Match table fields to a 32-bit gather

Probability precision, physical word width and state width are different knobs.
In P12 mode, frequencies are quantized to a total of 4096, then multiplied by 16
to retain the existing 65536 codeword domain. Physical words remain 16 bits: this
does **not** store padded twelve-bit words and waste four bits per output word.

An aligned sixteen-codeword interval shares symbol, scaled frequency and scaled
remainder. Its descriptor fits exactly in a u32:

```
symbol:8 | (frequency/16 - 1):12 | (remainder/16):12
```

The decoder gathers once from 4096 entries (16 KiB), and recovers the remaining
four remainder bits from the codeword. Construction checks this alignment for
**every** codeword, including the alias mapping. The P16 control instead needs
two u32 gathers from 65536-entry tables. Its lookup occupies 512 KiB.

The 16 KiB figure is the main SIMD lookup, **not total model allocation**. The
research object also retains scalar-oracle tables and frequency/start/reciprocal
arrays. Encoding uses three 256-entry u32 arrays (3 KiB).

Increasing probability precision to 32 bits is not an automatic SIMD win: a
direct u32 lookup over that whole domain alone would occupy 16 GiB. It also
changes arithmetic bounds. A 32-bit-probability design would need a different
lookup strategy, not merely larger constants in this kernel.

### 3. Convert variable control decisions into masks

The decoder compares sixteen capacities together. A mask selects physical reads
versus virtual low words. `VPEXPANDW` loads exactly the mask's population count
of consecutive physical words into the selected lanes; the other lanes use their
existing numerator. This uses AVX-512 VBMI2, not an assumed padding area. See the
[Rust intrinsic definition](https://doc.rust-lang.org/src/core/stdarch/crates/core_arch/src/x86/avx512vbmi2.rs.html)
and [Intel instruction reference](https://cdrdv2-public.intel.com/671110/325383-sdm-vol-2abcd.pdf).

The encoder's forward pass validates symbols and records one physical mask per
sixteen symbols: 1/8 byte of scheduling workspace per symbol. Its backward pass
uses exact SIMD reciprocal division with correction, embeds cumulative intervals,
and uses masked compression/stores to write only physical words. The reported
encoding time includes **both passes**, validation, exact output-size checking,
tails and state initialization. It is not just a timed arithmetic inner fragment.

The scheduling masks depend on frequencies, independently of the information
numerator. That property is preserved. However, SIMD interleaving, cumulative
mapping and table packing are not advantages exclusive to DC or novelty claims.

### 4. Hide latency across vectors; inspect the actual assembly

The window-reading alias control, with identical lookup layout and delay, shows:

| Number of states | P12 decode ns/symbol | P16 decode ns/symbol |
| --- | ---: | ---: |
| 16 | 1.1229 | 1.8542 |
| 32 | 0.6126 | 1.0245 |
| 64 | 0.4138 | 0.9203 |

This supports a latency-hiding explanation for the initial scaling, followed by
diminishing returns. The selected P12 masked-load decoder reaches 0.3924.

Assembly inspection found software population-count sequences because POPCNT
had not been explicitly enabled. It also found state arrays spilled by the
group loop. Explicit POPCNT and group expansion removed those avoidable costs.
The selected P12 hot loop keeps all eight state/capacity vectors in registers;
stack copies occur only when handing off the final scalar tail.

## How close is this to a limit?

**The 1 ns target is met. An absolute hardware or DC algorithm limit is not proved.**

A useful lower-bound model is the maximum of:

```
dependency-chain cycles / independent symbols in flight
required uops on each execution resource / that resource's issue rate
input/output traffic / sustainable bandwidth at the relevant cache level
```

Resource sharing, mask-to-address dependencies and frequency changes matter.
Counting branches, or dividing the number of instructions by SIMD width, does
not establish a speed limit.

### Hardware evidence

Perf events were enabled only around the seven timed samples through acknowledged
control FIFOs: model construction, allocation, file reads and correctness oracles
were excluded. Each counter run covered 1878107553 symbols. Raw commands and
outputs are [preserved here](results/2026-09-14-avx512-counters.txt).

- P12 decoder: **1.213 cycles/symbol**, about **3 branch misses per million
  symbols**. Unpredictable branches are no longer the dominant obstacle.
- P16 decoder: **2.843 cycles/symbol**. About 40.0% of counted cycles were
  execution stalls with an outstanding L1 miss, but only about 0.04% with an
  outstanding L2 miss. This supports an L2-resident lookup bottleneck.
- P12's corresponding L1-miss stall fraction was about 0.14%. Its port-0
  dispatch rate was about 0.775 uops/cycle. Together with the dependency analysis,
  this points toward execution-resource pressure and recurrence latency.
- P12 encoder: **2.513 cycles/symbol** in its counter run. That longer instrumented
  run measured 0.9084 ns/symbol, versus the separate short paired-run median of
  0.8577. Frequency is not pinned; do not convert every row using one assumed GHz.

These stall events overlap and are not additive time partitions. Preliminary
generic L1 load/miss counters even produced a percentage above 100% for gathers;
those incompatible event populations are **not** interpreted as a cache hit rate.
The table-size/precision comparison changes lookup instructions as well as cache
behavior; it is not an isolated cache-only causal ablation.

### Static throughput and dependency model

The actual P12 bounded hot loop is checked in as
[assembly](experiments/avx512-prototype/analysis/decode-p12.s). LLVM-MCA 23 with
the `sapphirerapids` model reports, per 64-symbol iteration:

- Resource-only block reciprocal throughput: **60 cycles**.
- Simulated execution including dependencies: **76.36 cycles** over 100 iterations.
- Actual hardware counters: approximately **77.63 cycles**.

At the approximately 3.09 GHz inferred for this decoder run, those correspond to
**0.30 ns/symbol** for the resource-only model and **0.386 ns/symbol** for the
dependency simulation, compared with **0.392 ns/symbol** measured. The simulation
identifies port-0 pressure and the capacity/mask/input/gather/update chain.
Its output is [retained](results/2026-09-14-avx512-mca.txt).

Thus **roughly 0.30 ns/symbol is an optimistic local target for this instruction
mix**, not a guaranteed achievable speed or a lower bound on every DC design.
LLVM-MCA's gather latency, mask handling and scheduling are models, not silicon
proofs. The agreement with one benchmark is encouraging, not validation on all
inputs. A different layout or arithmetic kernel changes the modeled bound.

For perspective, writing the same u32 output buffer without decoding costs
0.1352 ns/symbol; copying u32 input to output costs 0.2843. These are useful
memory controls, **not strict entropy-decoding lower bounds**: they have different
traffic, instruction selection and dependencies.

## Boundaries and regressions

At 65536 symbols, separate P12 synthetic checks gave:

| Input distribution | Encode ns/symbol | Bounded decode ns/symbol | Payload bytes |
| --- | ---: | ---: | ---: |
| Uniform 256 | 0.8593 | 0.4084 | 65730 |
| Skewed | 0.8720 | 0.4011 | 41558 |
| Near constant | 0.9120 | 0.4106 | 1288 |
| Constant | 0.9684 | 0.4259 | 128 |

These are single-process seven-sample medians, not five-run replications. Models
are normalized from the generated observations, using the same rule as file
input. They are not the old shared harness's fixed synthetic models. Uniform
data expands slightly; near-constant delay16 payload is 7.33% larger than its
same-model/delay24 1200-byte control. [Raw results](results/2026-09-14-avx512-boundaries.txt).

The older full-window decoder slows to 8.14 ns/symbol on constant input because
it falls back after the physical bytes are exhausted. The masked-load decoder
continues vector processing with zero physical reads and fixes this case.

Sixteen-symbol blocks remain slow: about 5.41 ns/symbol encoding and 9.17 decoding
in the tested case. Startup, scalar tails, and 64-lane over-provisioning dominate.
This is a **large-block/batched fixed-model** result, not a tiny-record result.

No AVX-512 rANS implementation was compared in this experiment. Comparing this
64-state AVX-512 result with an eight-state SSE baseline would not isolate a DC
algorithm advantage. Conditional-model SIMD, record-level seek performance and
Blitzcrank integration remain unimplemented here.

## Reproduction and validation

Xeon Platinum 8474C, Linux x86-64, CPU 2 affinity; L1D 48 KiB, L2 2 MiB/core.
Rust 1.92.0 / LLVM 21.1.3, Release, thin LTO, one codegen unit. No global native
CPU flags. Kernels explicitly enable AVX2, AVX-512F/BW/VL/VBMI2 and POPCNT, guarded
by runtime detection. Models and data are warmed; no assistant compilation or
tests ran concurrently with measurements. Machine-wide isolation is not claimed.

book1 has 768771 bytes, SHA-256
`9ffa47cd93bccd732f20e0c304203cfbc1b8a91bedac536e2d8f6051003d9951`, from unchanged
ryg_rans `c9d162d996fd600315af9ae8eb89d832576cb32d`.

```sh
cargo build --release --manifest-path benchmarks/experiments/avx512-prototype/Cargo.toml
taskset -c 2 benchmarks/experiments/avx512-prototype/target/release/dc-avx512-prototype /tmp/ryg_rans/book1 12
taskset -c 2 benchmarks/experiments/avx512-prototype/target/release/dc-avx512-prototype /tmp/ryg_rans/book1 16
DC_BENCH_CODEC=dc16_cumulative_bounded_64 taskset -c 2 \
  benchmarks/experiments/avx512-prototype/target/release/dc-avx512-prototype synthetic:constant 12 65536
llvm-mca-23 -mcpu=sapphirerapids -iterations=100 -bottleneck-analysis \
  benchmarks/experiments/avx512-prototype/analysis/decode-p12.s
```

Validation: independent division-based encoder and u64 scalar decoder;
byte-for-byte agreement with the supported original DC encoder at eight lanes;
all 65536 frequencies tested at u32 division boundaries; short tails, zero and
sparse models, exact buffers, untouched prefixes, invalid IDs and malformed
streams; Release tests and all-target Clippy pass. Rust AddressSanitizer tests
pass with nightly `809936eac` (2026-09-12), including the SIMD kernels. Root
workspace all-feature tests pass. These are correctness/safety checks, not a
release security audit; the new prototype is not in remote CI or a supported API.

The main crate still forbids unsafe code. The prototype is an independent,
unpublished research crate; its raw format requires external mapping identity,
lane count, frequencies and symbol count. Existing DC/Log-DC/C ABI formats and
Blitzcrank files have not been changed.
